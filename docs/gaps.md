# ice parity porting plan

Working plan for bringing ice-rust to feature parity with TypeScript ice. The gap specification is [`ice-gap/`](ice-gap/README.md); this file is the order of work and the progress tracker. Generated from [`ice-gap/evidence/porting-order.csv`](ice-gap/evidence/porting-order.csv) and the README all-entry index, audited against ice `3ab0519` and ice-rust `1891337`.

**791 gaps:** 351 missing, 404 partial, 36 different-by-design. **Priority:** 108 P0, 506 P1, 163 P2, 14 P3.

## How to work a gap

1. Take the next unchecked row in the [ordered list](#ordered-gap-list) whose prerequisites are done. Rows sharing a group (`G…`) depend on each other and are planned together.
2. Read the entry in `ice-gap/<area>.md`: field 4 (how it works) and field 5 (interfaces) are the spec. Read the ice tests it cites under `~/Zks/ice/packages/*/test/`.
3. Branch off up-to-date `main`: `feat/<crate>-<short-desc>`. One gap, or one dependency group, per branch (AGENTS.md §7.2).
4. Implement in the crate that owns the behavior (AGENTS.md §4). Add faux-provider tests mirroring the ice tests; a fix to existing behavior needs a regression test that fails first.
5. Pass the CI gates (AGENTS.md §5):
   ```bash
   cargo fmt --all -- --check
   RUSTFLAGS="-D warnings" cargo check --workspace --all-targets --locked
   RUSTFLAGS="-D warnings" RUSTDOCFLAGS="-D warnings" cargo test --workspace --locked
   sh scripts/sync-embedded-docs.sh && git diff --exit-code -- crates/ice-cli/embedded-docs
   python3 scripts/test_prebuilt_release.py
   ```
6. Open a PR into `main` citing the entry ID and ice source paths. Mark the row done here (`[x]` plus PR link) in the same PR.

Rules that apply to every gap: never touch `~/.ice`, `.ice/` or `ICE_*` (use `~/.icers`, `.icers/`, `ICERS_*`); tests use no network and a temp `ICERS_CODING_AGENT_DIR`; MSRV 1.78; keep PRs under ~600 changed lines excluding tests.

## Open decisions

These need an owner decision before the affected gaps can close (see [ice-gap README](ice-gap/README.md#open-questions-and-evidence-limits)):

- Compatibility policy for deliberately different native runtime identities, persisted formats and malformed-input defenses.
- Whether visual-only `/clear` stays separate from true `/new` semantics (RUST-066).
- Plugin package names and ABI symbol before any `icers install` work (AGENTS.md §2.6).
- `ultra` thinking level (AI-005) and built-in `zai`/`opencode` providers (ICE_PORTING.md §11a).
